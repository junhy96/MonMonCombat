# 몬몬 마스터즈 레벨 디자인 과제 — 전투 시뮬레이션

플레이하드 「몬몬 마스터즈」 기획 과제(던전 = 퍼즐, 캐릭터 = 열쇠)의 근거를 만드는 파이프라인입니다.
목적은 **"이 던전에서 열쇠가 정말 열쇠인가"를 숫자와 전투 장면으로 보여 주는 것**입니다. 시뮬레이션이 기획 답을 대신하지 않고, 답안의 주장을 뒷받침합니다.

## 문항별로 보여 줘야 하는 것

| 문항 | 파이프라인이 보여 줄 것 |
|---|---|
| 1-1 원인 | 열쇠 있음·없음의 성장 단계별 클리어율 곡선이 붙어 있는가 / 보스 위협 시각 vs 열쇠 첫 발동 시각 / 열쇠가 발동 전에 쓰러지는 비율 / 열쇠 효과량 vs 위협량 |
| 1-2 변경안 | 열쇠 없이 같은 클리어율을 내려면 필요한 추가 성장(= 열쇠의 가치) / 열쇠가 있어도 필요한 최소 성장 — 난이도 단계별 |
| 1-3 플레이어 경험 | 플레이어 상태 × 단계 × 열쇠 유무 클리어율 표 + 한 단계 아래 클리어율·보상 → 실패 후 행동(아래 단계 반복 / 열쇠 육성 / 열쇠 구하기) |
| 2-1 에픽 열쇠 던전 | 열쇠 없는 곡선이 성장해도 평평함, 로그에서 막히는 이유가 보임 |
| 2-2 다른 해법 | 열쇠를 뺀 풀로 조합 자동 탐색 → 대체 해법 후보 |

## 구성

```
src/combat/   파티 전투 엔진 (파티 vs 적·보스, 웨이브, 스킬 게이지, 패시브, 실시간·턴제)
src/data/     데이터 테이블 구조(schema.js)·검증·CSV(tables.js)·기본 예시 데이터(tables.json)
src/lib/      시드 고정 난수, ZIP
tools/        combat-data-template.mjs — 데이터 입력 엑셀 템플릿 만들기
              effect-icons.mjs — 효과 캡처에서 아이콘 자르기 + 효과 목록(data/effects)
              growth-fit.mjs — 레벨 강화 관측값 → 등급별 성장 배율(data/growth)
              capture/, ocr/ — 게임 도감 캡처와 글자 읽기 → data/monmon
templates/    combat-data-template.xlsx — 게임에서 모은 수치를 적는 파일
tests/        node --test
```

`src/`는 워크벤치(planning-workbench)의 `js/combat`·`js/data`에서 화면 코드 없이 계산 부분만 옮겼습니다. 화면 공용 라이브러리 대신 쓰던 순수 함수만 `src/lib`으로 뽑았습니다.

## 전투 규칙 (게임에서 확인한 것)

- 평타는 자동, 스킬은 게이지가 가득 차면 발동. 게이지는 시간으로만 차고 속도가 높을수록 빨리 참. 속도는 평타 주기에도 영향
- 게이지가 차면 전투 전체가 멈추고 스킬을 반드시 씀 → 시뮬레이션에서는 0초
- 캐릭터: 액티브 1개 + 패시브 여러 개, 시작 게이지는 캐릭터마다 다름
- 보스: 보스용 게이지, 찰 때마다 스킬 목록 순서대로
- 웨이브: 전환 연출은 전투 시간에 안 들어감, 아군 체력 유지, 게이지는 시작값으로
- 전열/후열은 캐릭터가 아니라 배치로 정함
- 속도 100이면 **평타 10번 뒤에 스킬 1번** (사용자 관측, 2026-11-25) → 1턴 ≈ 평타 10번 + 스킬 1번
  - 피해 크기 예시 (사용자 관측, 몬몬 1명): 평타 1방 ≈ 120, 스킬 1방 ≈ 4,000 → 스킬이 평타 약 33방, 1턴 화력의 약 3/4
- 보스는 속도 100이면 **평타 4번 뒤에 스킬 1번** (사용자 관측, 2026-11-25) — 몬몬(10번)과 다름
- 속도 120 보스의 스킬 사이에 아군 몬몬(속도 100)은 **평타 약 5번** (사용자 관측) → 같은 시간에 몬몬이 보스보다 더 자주 때림
  - 보스 게이지가 속도에 비례한다고 보면 보스 스킬 한 주기 ≈ 아군 평타 5 × 120 ÷ 보스 속도번 시간 (속도 100 보스 = 평타 6번 시간 → 보스 평타 간격 ≈ 몬몬의 1.5배)
  - 아군 스킬은 평타 10번 시간마다 1번 (게이지가 차면 전투가 멈추고 쓰므로 0초)
- 파티 5명 (사용자 확인)
- 글라틀 [얼음 등껍질]의 "공격 횟수"에는 **평타도 1번씩 들어감** (사용자 확인)
- 턴: 1턴 = 몬몬이 스킬을 한 번 쓸 때. 버프·디버프 지속은 턴으로 표시되고 **효과를 받은 몬몬의 턴**으로 셈 (엔진 `effectDur: 'turn'`, 기본값)
  - 스킬을 쓴 뒤 1 감소 → 2턴 버프는 받은 몬몬의 스킬 2번에 적용
  - 자기 스킬로 자신에게 건 효과는 그 스킬에서는 줄지 않고 다음 스킬부터
  - 기절 중에도 게이지가 차고, 차면 스킬 없이 턴만 소모 (기절 1턴 = 스킬 한 번을 잃음)
  - 지속 피해·지속 치유는 받은 몬몬의 턴마다
  - 대기시간은 효과를 쓴 몬몬의 턴으로 셈 — 엔진에 아직 대기시간 효과 없음
- 효과 목록: `data/effects/` — 버프 19종·디버프 20종을 약/강으로 나눈 62개와 아이콘. 치명확률·치명피해는 증가·감소 모두 합연산으로 적용 (다른 게임 관례 기준, 게임에서 확인 전)
- 레벨 성장: 곱연산, 레벨당 배율은 지금 별 개수로 정해짐 — 1성 ×1.0802 · 2성 ×1.0342 · 3성 ×1.0204 · 4성 ×1.0136 · 5성 ×1.0107 (관측에 맞춘 근사값, 태생 5성은 아직 없음). 진화하면 Lv1부터 다시, Lv1 스탯이 약 1.36~1.43배 — `data/growth/`
- 몬몬 도감: `data/monmon/` — 285개 스탯·스킬(게임 캡처 OCR). 스탯은 도감 화면 값이라 계정 보너스가 들어 있음

확인 전인 규칙(동시 발동 순서, 웨이브 사이 버프, 평타 주기 재시작, 한 턴 안에서 지속 피해가 스킬 앞/뒤 중 언제 들어가는지)은 엔진 규칙 선택지로 두었습니다 — `src/combat/engine.js`의 `DEFAULT_RULES`.

엔진의 한계: 액티브 스킬이 없는 유닛은 턴이 오지 않아 그 유닛에 걸린 턴 지속 효과가 끝나지 않습니다. 보스 그로기(흐트러짐)는 아직 초 단위입니다.

## 다음 할 일

1. 엑셀 가져오기: 템플릿 → 데이터 테이블, 빈 칸·모르는 값 목록
2. 보정: 관찰 시트(피해·스킬 주기·전투 결과)로 데미지 공식·충전 속도 맞추기, 실제 결과와 비교
3. 타이밍 진단: 보스 웨이브의 유닛별 첫 발동 시각, 보스 스킬 시각, 열쇠 발동 전 사망률 — 레벨 디자인(보스 행동·열쇠 스킬·시작 게이지)이 의도대로 동작하는지 확인
4. 성장 점검표: 새 기능 없이 교체 비교(열쇠 있음/없음)를 파티 레벨 몇 단계(지금 / +10 / +20 또는 스탯 배율)로 돌린 표 — 1-2·2-1의 성장 조건 확인용
5. 난이도 단계 묶음 실행과 보고서(HTML)

성장 곡선(레벨마다 촘촘한 그래프)은 만들지 않습니다. 문제에서 요구하지 않고, 데미지 공식·스탯이 추정인 상태에서는 몇 개 지점의 상대 비교로 충분합니다.
